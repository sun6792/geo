## 三、闭环完整性验证

### 全闭环流程 (逻辑验证)

```
探测(Agent1) → 诊断(Agent2) → 创作(Agent3) → 审核 → 发布(Agent4) → 复盘(Agent5)
    ↑                                                                       │
    └──────────── 下一轮探测任务自动生成 ← 优化策略自动创建 ←────────────────┘
```

| 环节 | 输入 | 输出 | 状态 |
|------|------|------|------|
| 探测 | 关键词 + 模型 + 竞品配置 | detection_results 入库 | ✅ |
| 诊断 | 探测结果 + KB 资产数据 | 诊断报告 + 五维评分 + 优化任务 | ✅ |
| 创作 | 优化任务 (可关联 brief) | content_drafts 生成 | ✅ (P0) |
| 审核 | 稿件 | 双审状态流转 | ✅ (P0) |
| 发布 | 审核通过稿件 | 发布记录 + 效果数据 | ✅ (P0) |
| 复盘 | 探测数据 + 发布表现 + KB 增长 | 周度报告 + 下一轮策略 | ✅ |
| 迭代 | 新策略 | 新建探测/优化任务，进入下一轮 | ✅ |

### 数据流转正确性
- ✅ 探测结果 → 诊断分析: `_analyze_detection_data()` 正确聚合 detection_results
- ✅ KB 资产 → 诊断缺口: `_scan_kb_gaps()` 正确统计三层资产
- ✅ 探测+发布 → 周度复盘: `_aggregate_weekly_metrics()` 跨表聚合正确
- ✅ 诊断结果 → 优化任务: `_generate_optimization_tasks()` 按缺口+模型自动生成
